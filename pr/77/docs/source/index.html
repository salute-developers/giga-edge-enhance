GigaEdge Enhance is a cross-platform SDK for real-time speech enhancement. It adds neural noise suppression, loudness normalization, and, on supported platforms, acoustic echo cancellation to native, mobile, and web applications.

The browser demo is published with the documentation site. The capability matrix shows which features and models each SDK exposes. Release archives and the Web SDK npm tarball are described in Distribution.

#include <giga-edge-enhance.h>

#include <vector>

int main() {
  giga_edge::enhance::Denoiser denoiser("models/quality48/onnx/config.yaml");
  auto* context = denoiser.CreateContext(48000, 48000);

  std::vector<float> input(denoiser.GetModelInputFrameSize());  // Fill with mono PCM in [-1, 1].
  std::vector<float> output;
  const auto code = denoiser.ProcessChunk(input, output, context);
  denoiser.DestroyContext(&context);
  return code < GigaEdgeEnhanceRetCode::SUCCESS ? 1 : 0;
}

Prepare the pipeline before a real-time callback. ProcessChunk can return success before it emits a full buffer while the model collects overlap. The C and C++ quickstart shows the streaming loop, GetFinalChunk, and the C API.

Use a release​

Pin a GitHub Release. Each release contains the tested native, Android, iOS, and Web SDK archives. The Web SDK archive is an npm tarball. The release workflow does not publish that tarball to the npm registry.

A native archive exports the CMake package giga-edge-enhance:

find_package(giga-edge-enhance CONFIG REQUIRED)
target_link_libraries(your_app PRIVATE giga-edge::enhance)

Android and iOS packages are consumed as described in their SDK guides. The repository build can produce the same native archive locally with tools/package.

Build the repository​

This path is for contributors. Git LFS restores models and test audio. Docker is the default toolchain for native Linux, WebAssembly, Web, and Android; Apple and Windows targets use their host toolchains.

git lfs install
git lfs pull
tools/build native-debug-onnx
tools/test native-debug-onnx

Supported commands, presets, and packages are documented in tools. Build outputs are written under out/.
