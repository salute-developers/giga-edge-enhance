Development tools

Run every command from the repository root. The scripts in this directory are the supported interface for configuring, building, testing, installing, and packaging GigaDenoiser. Prefer them to ad hoc CMake, Docker, Gradle, Xcode, or npm command chains.

Docker is the default for native Linux, WebAssembly, Web, and Android work. Host mode is retained for explicit manual troubleshooting only; normal builds, tests, and reported validation must omit --host. macOS, Windows, and iOS targets use their required host toolchains implicitly.

Commands​

tools/build TARGET [--host]
tools/test TARGET [--host]
tools/package TARGET [--host]
tools/install TARGET [--host]
tools/shell
tools/ci ACTION ...

build creates build output. test, package, and install consume an existing build produced with the same target and execution mode.

Test​

All native targets except native-model-packer can be passed to tools/test. All macOS and Windows targets listed under Build can also be tested. Native and WebAssembly tests accept --host; desktop targets do not.

tools/test native-debug-onnx [--host]
tools/test native-release-onnx [--host]
tools/test native-debug-tflite [--host]
tools/test native-release-tflite [--host]
tools/test native-release-static-onnx [--host]
tools/test native-release-static-tflite [--host]
tools/test native-asan-onnx [--host]

tools/test wasm-debug [--host]
tools/test wasm-release [--host]
tools/test wasm-dsp-debug [--host]
tools/test wasm-dsp-release [--host]

tools/test android [--host]
tools/test android-ui
tools/test ios
tools/test web [--host]
tools/test web-playwright [--host]

android-ui requires Linux KVM and always uses the Android UI container. iOS slice presets do not have standalone CTest suites; use tools/test ios.

Package​

tools/package native-release-onnx [--host]
tools/package native-release-tflite [--host]
tools/package web [--host]

Packages are written below out/artifacts/. Build the same target first.

Install​

tools/install supports every native target except native-model-packer, plus all macOS and Windows targets listed under Build. It installs below out/artifacts/install/TARGET and builds an external CMake consumer to verify the installed package.

tools/install native-release-onnx [--host]
tools/install macos-arm64-release-onnx
tools/install windows-x64-release-tflite

Shell​

tools/shell

This opens the native Linux development container at /workspace. The repository is mounted read/write, and the host home is mounted at /host-home. /host-home becomes the shell's home, so cd ~ opens the host home and makes files such as ~/Music/input.wav available to containerized command-line tools. Project caches remain under /workspace/out/cache.

The shell does not build automatically. Build a native target first, then run its tools from out/build/container-clang-llvm-tools/TARGET.

CI Operations​

These commands support composite actions and workflows. Contributors normally do not need them for source-level work.

tools/ci image-key {native|web|android|android-ui}
tools/ci recipe-key {native|web|android}
tools/ci cache-key TARGET [--host]
tools/ci prepare-deps TARGET [--host]
tools/ci dependency-key TARGET [--host]
tools/ci dependency-archive TARGET [--host]
tools/ci restore-deps TARGET ARCHIVE [--host]

prepare-deps accepts these group aliases in addition to concrete targets:

android
web
ios
macos
windows

Concrete dependency targets are native ONNX/TFLite targets, wasm-debug, wasm-release, all macOS and Windows ONNX/TFLite targets, all four iOS slice targets, and:

android-release-tflite-arm64-v8a
android-release-tflite-armeabi-v7a
android-release-tflite-x86_64
android-release-tflite-x86

native-model-packer and wasm-dsp-* do not use inference-engine dependency bundles.
